# Проверки и границы готовности

## Версия 0.3

Добавлены отдельные пакеты `adaptive` и `research`, девять live-сценариев,
три абляции и серия из 13 сценариев. Оценки уточняются по наблюдениям;
это снимает ограничение фиксированной оценки только у нового метода.
Прежние методы сохранены. Остаточные ограничения ниже в части сетевых
агентов, криптографии и идеализированных текущих очередей остаются в силе.

Проверки включают причинность (изменение будущего не меняет прошлые решения),
воспроизводимость, бюджет, сроки, перестановку входов и автоматическую
генерацию доказательного отчёта. `FuzzBudgetAndDeterminism` перебирает входы
планировщика. Все прогоны `research` независимо сверяются с журналом сообщений.

DOM-проверка покрывает девять сценариев, график обучения, готовые кадры,
импорт v3, отклонение испорченных оценок и офлайн-файл с пятью опытами.
Это проверка логики интерфейса, не измерение CSS-layout в настоящем браузере.

```bash
go test -race -cover ./...
go test ./internal/adaptive -run '^$' -fuzz FuzzBudgetAndDeterminism -fuzztime 5s -parallel 2
go test ./internal/adaptive -run '^$' -bench BenchmarkChoose12 -benchmem
go run ./cmd/relaylab research -runs 30 -seed 1000 -out results/check
```

Подробности интерпретации: [как доказывать эффективность](proof-guide.md).
Подробности допущений и первичные научные источники: [алгоритм](adaptive.md).

## Сохранённая проверка версии 0.2

Версия 0.2 включает вычислительную модель и интерфейс демонстрации.
Утверждение о готовой промышленной распределённой системе было бы неверным.

## Автоматические проверки

```bash
go test -race -cover ./...
go vet ./...
go test ./internal/selector -bench . -benchmem
```

Тесты покрывают:

* четыре точных контрольных расчёта и согласие Монте-Карло с ними;
* нулевой бюджет, неизвестные и ошибочные метки, старение и равенство оценок;
* сохранение назначений при продолжении выбора и невозможность выдать бюджет заново;
* все шесть временных сценариев на пяти стратегиях;
* вместимость очередей и соответствие занятых байтов копиям и резервам;
* баланс созданных, доставленных, истёкших, отклонённых и ожидающих сообщений;
* отказ внутри интервала передачи, потерю ACK и устранение повторных записей;
* воспроизводимость и независимость результата от включения журнала;
* JSON API, встроенные ресурсы, отклонение неверных входных данных и остановку сервера;
* запрет внешней привязки демонстрационного HTTP-сервера, проверку Host и Origin.
* совпадение офлайн-журнала с результатом Go и воспроизведение сохранённой конфигурации;
* контроль SHA-256 файла конфигурации и запрет перезаписи предыдущих результатов.

Проверочный запуск от 23.10.2026: `go test -race -cover ./...`, `go vet ./...`
и сборка завершились успешно на Go 1.27.3 linux/amd64. Покрытие пакета selector
составило 97,8%, временного движка 94,8%. Покрытие не означает доказательство
корректности всех возможных конфигураций. В GitHub Actions добавлена проверка
на Go 1.22 и текущем стабильном выпуске; её результат нужно смотреть отдельно.

Тест `tools/dom-smoke.cjs` использует реальные журналы, сформированные Go,
и проверяет компоненты интерфейса через jsdom: шесть сценариев, цифры на экране,
воспроизведение, скачивание, повторное открытие и отклонение неверного журнала,
восстановление после ошибки API, запуск самостоятельных HTML двух разных сценариев.
Это проверка DOM и логики; она не проверяет реальные размеры шрифтов и CSS-layout.

Для повторения нужно установить jsdom 26 в среде тестирования, собрать
`relaylab` и выполнить `RELAYLAB_BIN=/путь/к/relaylab node tools/dom-smoke.cjs`.
Если jsdom установлен отдельно, путь к модулю задаётся через `JSDOM_MODULE`.

Для дополнительной проверки в обычном Chromium есть `tools/ui-smoke.cjs`.
Нужны Node.js и установленный Playwright. Самому приложению они не нужны.

```bash
# В отдельной среде разработки с Playwright:
node tools/ui-smoke.cjs
```

Сначала запустить `relaylab serve`. Переменные: `DEMO_URL` (по умолчанию
http://127.0.0.1:8080), `CHROME_BIN` (необязательный путь к Chromium),
`QA_SCREENSHOT_DIR` (по умолчанию results/ui-smoke).

При разработке этой версии нативный Chromium в исполнительной среде не
смог запуститься из-за ограничения создания сокетов. Поэтому полный
браузерный тест и визуальная проверка desktop/mobile здесь не подтверждены.
Перед выставкой следует выполнить этот тест и посмотреть страницу на том
компьютере, который будет использоваться на стенде.

## Остаточные ограничения

* Оценки доступности фиксированы, мгновенная информация о текущих очередях идеализирована.
* Сохраняется топология «источник → ретранслятор → collector», без обмена между ретрансляторами.
* Криптография, дисковое хранение и восстановление после перезапуска пока не реализованы.
* Сетевой расход учитывает полные попытки передачи и условные ACK; накладные расходы TLS/IP отсутствуют.
* Офлайн-HTML воспроизводит один сохранённый опыт и не пересчитывает параметры.
* Встроенные сценарии иллюстрируют поведение, но не представляют измеренное распределение отказов реальной площадки.
* Настройки не оптимизированы по независимой обучающей выборке, научное превосходство не установлено.

Следующий инженерный этап — устойчивые сетевые Go-агенты, воспроизводимые
отказы в Linux и измерение фактического трафика. Следующий исследовательский
этап — отделить настройку параметров от итоговых сценариев и проверить,
даёт ли совместный учёт доступности и риска выигрыш над простым разнесением.
